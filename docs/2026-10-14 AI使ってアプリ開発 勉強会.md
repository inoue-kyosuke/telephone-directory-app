# 2026/10/14 AI使ってアプリ開発 勉強会

## 会の概要

この勉強会の主な目的は、Claude Codeを使ったAI開発の検証です。既存システムへのハーネス展開は対処に時間がかかる見込みのため、新規アプリの開発を通じて「ハーネス → ループエンジニアリング」を検証します。あわせて、社内ツールを低コストで作れる基盤としてCloudflare環境も試します。第2回は、勉強会の進め方を共有したうえで社内標準テンプレートを紹介し、全員でデプロイとAccessの確認まで行います。

- **題材**：電話取次支援アプリ（会社で運用する想定。取引先担当者の氏名・電話番号などの個人情報を扱う）
- **検証テーマ**：①Claude Codeのハーネス整備からループエンジニアリングへ ②Cloudflare（Workers / D1 / Access）での社内ツール開発
- **進め方**：仕様書 → 画面モック → DB設計 → 実装の順に、全員が同じものを各自のClaude Codeで作る。同じものを作ることで、AIの設定や依頼の仕方の違いを比較する
- **レビュー**：成果物ごとに相互レビュー会を行い、実装完了後にAI設定・ハーネス・ループを含めた総まとめのレビュー会を行う

**事前準備**

* [ ] 全員：Cloudflareアカウントの権限付与とAccessの初期設定
* [ ] 全員：GitHubで勉強会用リポジトリにアクセスできることを確認
* [ ] 全員：Dockerをインストールし、起動できることを確認

## 議題の詳細

### 1. 勉強会の目的・進め方・スケジュールの共有

- **AI開発の検証**：既存システムへのハーネス展開は時間がかかるため、新規アプリで検証する。まずハーネス（テスト・型・Lint・Formatなど、AIが自分の作業を確かめられる仕組み）を整え、その上でループ（調査 → 実装 → テスト → 修正 → 再テストをAIに回させる仕組み）を検証する
- **全員が同じアプリを作る理由**：仕様をそろえることで、AIの設定や依頼の仕方による違いを比較できるようにする
- **Cloudflareの検証**：社内ツールを低コストで作れる基盤かどうかを体験ベースで確認する
- **進め方**：会では最低限の共通仕様だけを決め、ループの回し方やデザインドキュメントなどの進め方は各自の任意とする。成果物ごとに相互レビュー会を行う（下記「今後の予定」「相互レビュー会の想定」参照）
- **記録してほしいこと**：AI設定一式（CLAUDE.md、設定ファイル、hooks、スキルなど）、主な依頼の仕方、人が介入した回数と内容、かかった時間の目安、Cloudflare側でつまずいた点

### 2. 社内標準テンプレートの紹介（益岡）

- 構成：Docker / Wrangler / Hono / Access JWT検証ミドルウェア / CI/CD（GitHub Actions）
    - <https://github.com/masuoka-hcompany/call-memo-book/tree/chore/cloudflare-template> 
- テンプレートにはAI設定（CLAUDE.md等）を含めず、各自で整える

### 3. 振り返りと次回の宿題の確認

つまずいた点をテンプレートの改善点として記録し、次回（機能要件の精緻化）に向けた宿題を確認します。

| 回 | 会で行うこと | 次の会までに各自で進めること（進め方は任意） |

| 第3回 | 機能要件の精緻化（話し合い）、開発中のデータルール | 仕様書をマークダウンで作成・提出 |
| 第4回 | レビュー会①：仕様書（最後に完了条件をそろえる） | 画面モック作成（動作なし）、Cloudflareへのデプロイ |

| 第6回 | レビュー会③：DB設計（最後にテーブル定義をそろえる） | ハーネスの整備（AI設定、テスト・型・Lint・Format、マイグレーション適用） |

## 相互レビュー会の想定

成果物ごとにレビュー会を行います。途中の会①〜③は成果物と依頼の仕方を中心に軽く回し、実装完了後の会④でAI設定・ハーネス・ループを含めた総まとめを行います。

| レビュー会 | 対象 | 主に見るもの | 最後にそろえるもの |
| --- | --- | --- | --- |
| ① | 仕様書 | 要件の解釈、書き方、AIへの依頼の仕方 | 完了条件 |
| ② | 画面モック | 画面構成と項目、使いやすさ、Cloudflareへのデプロイ | 画面に出す項目 |
| ③ | DB設計 | テーブル構成、「つなぐ/つながない」の単位、電話番号の正規化 | テーブル定義 |
| ④ | ハーネス | AI設定（CLAUDE.md、hooks、スキルなど）、テスト・型・Lint・Formatの整備状況、AIが自分の作業をどこまで確かめられるか | なし（良い工夫は各自で自由に取り入れる） |
| ⑤ | ループ | タスク管理の方法（GitHub Issue等）、調査 → 実装 → テスト → 修正 → 再テストがどこまで自動で回るか、人の介入回数 | なし（同上） |
| ⑥ | 機能実装と総まとめ | 下記「総まとめの観点」 | 良かった設定・やり方（社内標準へ反映） |

### 総まとめ（レビュー会④）の観点

同じ仕様で作っているので、違いがそのまま比較材料になります。

| 観点 | 見るもの |
| --- | --- |
| AI設定 | CLAUDE.md、設定ファイル、hooks、スキル、カスタムコマンドの中身と工夫 |
| ハーネス | テスト・型・Lint・Formatの整備状況、AIが自分の作業をどこまで確かめられたか |
| ループ | タスク管理の方法（GitHub Issue等）、調査 → 実装 → テスト → 修正 → 再テストがどこまで自動で回ったか、人の介入回数 |
| 依頼の仕方 | うまくいった指示・うまくいかなかった指示、デザインドキュメント等の使い方（作った場合） |
| 成果物 | 共通仕様の完了条件を満たしているか、仕様外の部分の作り方、コードの読みやすさ、テストの質 |
| Cloudflare | D1・Access・デプロイの使い勝手、つまずいた点、社内ツール基盤として標準化できそうか |

進め方は、1人あたり発表10分と質疑5分を目安に、最後に全員で「良かった設定・やり方」をまとめ、STEP2と今後の社内標準に反映します。
